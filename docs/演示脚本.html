选题：题三 热点发现 Agent + 题二 内容运营 Agent，均通过飞书推送形成真实闭环。

核心策略：两题都落在"AI 产品出海增长"这条主线上，与应聘的增长运营岗位强相关；飞书推送门槛低、可复用，保证"能运行、能演示"。

开场（30 秒）

我选了两道题，都围绕"AI 产品出海增长"这条主线，用飞书做真实闭环。先演示热点发现。

题三：热点发现 Agent（约 2 分钟）

1/4

实时抓取多源：运行脚本，展示 RSS（36氪/机器之心/HN/Reddit）+ GitHub Trending 实时抓取。

2/4

AI 筛选与摘要：强调 AI 做的是"筛选 + 摘要 + 价值评分 + 入选理由"，不是简单问答，对应评审"AI 使用"维度。

3/4

人工审核：停在审核节点，现场点"通过"，展示飞书群收到报告，对应"执行能力"+"风险控制"。

4/4

飞书推送 + 本地保存：展示推送结果和保存在 output/ 的报告文件。

演示要点：抓取是实时的，网络差时部分源可能失败，代码已做容错。GitHub Trending 源最稳定，优先保证它抓到数据。

题二：内容运营 Agent（约 2 分钟）

1/4

AI 生成热门选题：展示 AI 围绕"AI 产品出海增长"产出选题列表（标题/人群/角度/平台）。

2/4

AI 生成平台化内容：选一个选题，生成公众号风格完整内容。

3/4

人工审核：现场通过，对应"风险控制"。

4/4

飞书推送 + Word 文档：展示双输出，体现"收集 + 生成"双任务和"飞书 + 文档"双渠道。

收尾（30 秒）

诚实说明局限：AI 内容需人工把关质量、数据源依赖网络、飞书 webhook 有频率限制。对应"风险控制"维度。

评审五维度话术

评审维度你的话术
需求理解我把问题拆成"数据源 → AI处理 → 人工审核 → 推送"四段闭环。
AI 使用AI 不只是生成文本，还做筛选、价值评分、多源处理。
产品判断用户是增长运营，痛点是从海量信息里快速找到值得做的选题。
执行能力这是真实跑通的，飞书里那条消息就是刚才发的。
风险控制每个 Agent 推送前都有人工审核，且标注信息来源。
